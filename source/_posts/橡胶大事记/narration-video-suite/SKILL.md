# Narration & Video Prompt Suite Generator

## 概述

此技能专门用于将深度文章（如《橡胶大事记》等知识、科普、历史、金融系列文章）一键工业化转换为高品质视频制作资产。
**执行此技能时，必须首先为目标文章新建一个专属的独立文件夹，然后将标准化的“三件套”文件写入该文件夹中。**

---

## 核心工作流规范

当用户提供一篇文章（例如 `橡胶大事记/正文/1.2 橡胶的自然属性.md`）或要求为某内容生成视频旁白与提示词时，按以下步骤严格执行：

### 第一步：提取标题并新建专属文件夹

1. **提取主题简称/章节名**：从文件名或文章主标题中提取规范名称（例如 `1.2 橡胶的自然属性`）。
2. **确定目标目录**：
   - 如果原文章位于某主题的 `正文/` 目录下（如 `xxx/正文/`），则输出根目录应对应建立在同级的 `旁白/` 目录下。
   - 目标文件夹完整路径为：`.../旁白/{章节名}/`
   - **必须使用工具新建该文件夹**，严禁将文件散落在外层目录。

---

### 第二步：生成文件一 —— 完整导演分镜旁白脚本

* **文件名**：`{章节名}.md`（如 `1.2 橡胶的自然属性.md`）
* **定位**：供导演、剪辑师、创作者审阅的全局脚本，兼具视觉与听觉设计。
* **内容规范**：
  1. **元信息**：包含 Hexo YAML Frontmatter（title, date, tags, categories）。
  2. **解说总控参数**：标明解说风格（如“沉稳、知性、微观诗意”）、建议语速（200–220字/分）、预计总时长。
  3. **模块化分幕**：划分清晰的幕次（序幕、分幕 1~N、尾声）。
  4. **每一幕必备要素**：
     - `【预估时长】`：精确到秒（如 `00:00 - 00:45`）。
     - `【画面】`：具体镜头构图、机位、主体动作、色彩与光影说明。
     - `【音效/配乐】`：拟音细节（Foley）、环境音效与背景音乐情绪基调。
     - `【旁白】`：符合口语朗诵美感、文笔洗练、富有哲理与科学趣味的解说词。

---

### 第三步：生成文件二 —— 纯 SSML 语音合成标记脚本

* **文件名**：`{章节名}_SSML.md`（如 `1.2 橡胶的自然属性_SSML.md`）
* **定位**：专供 TTS 引擎（Edge-TTS、Azure Speech Studio、ElevenLabs、Fish Audio 等）使用的发音文件。
* **内容规范**：
  1. **彻底剔除非发音文本**：绝不允许出现任何画面描述、镜头角度、音效提示或括号注释，全篇仅保留需要发音的旁白词。
  2. **完整合规的 SSML 语法**：
     - 根标签：`<speak version="1.0" xmlns="http://www.w3.org/2001/10/synthesis" xmlns:mstts="https://www.w3.org/2001/mstts" xml:lang="zh-CN">`
     - 语速设置：包裹 `<prosody rate="-3%" pitch="0%">`（纪录片稳重语速）。
     - 结构组织：使用 `<p>` 划分大段，`<s>` 划分单句。
     - 节奏停顿：标点及气口处添加 `<break time="150ms~300ms"/>`，段落/幕次之间添加 `<break time="800ms"/>`。
  3. **严格的多音字与专业术语发音校准（`<sub alias="...">`）**：
     - 化学式/数字编号：如 `顺式-1,4-聚异戊二烯` 必须标注 `<sub alias="顺式一四聚异戊二烯">顺式-1,4-聚异戊二烯</sub>`，防止误读为“一点四”。
     - 生僻/多音字：如 `几丁质酶` 标注 `<sub alias="肌丁质酶">几丁质酶</sub>`。
     - 数值与单位：如 `10 到 15 个大气压` 标注 `<sub alias="十到十五个大气压">10 到 15 个大气压</sub>`；`700% 甚至 900%` 标注 `<sub alias="百分之七百甚至百分之九百">700% 甚至 900%</sub>`。
     - 核心概念重音：使用 `<emphasis level="moderate|strong">` 标记。

---

### 第四步：生成文件三 —— Google Flow / Veo 视频生成提示词

* **文件名**：`{章节名}_Google_Flow_提示词.md`（如 `1.2 橡胶的自然属性_Google_Flow_提示词.md`）
* **定位**：用于在 Google Flow（搭载 Veo 2 / Veo 3.1 视频生成模型）中直接复制生成视频分镜。
* **内容规范**：
  1. **1对1精准对齐 SSML**：将第二步的 SSML 旁白逐句拆解为有序的独立分镜（`Scene 01`、`Scene 02`……），便于音画对齐剪辑。
  2. **严格遵循 Google Flow 7 层导演公式**：
     > **[摄像机与镜头] + [主体] + [动作与物理表现] + [环境与时空] + [灯光与光影] + [风格质感] + [环境音频提示]**
  3. **每个 Scene 的必备字段**：
     - `【对应 SSML 旁白】`：对应单句或单段旁白文本。
     - `【Google Flow 英文标准提示词 (Prompt)】`：高水准英文 Prompt（包含专业摄影机、焦段、运镜指令、材质与物理模拟参数，可直接一键复制到 Google Flow）。
     - `【中文参考提示词】`：中文镜像描述，方便创作者核对视觉概念。
     - `【镜头与运镜】`：明确机位与运动方式（如 `Extreme Macro Close-up`, `Slow Dolly-In`, `3D Anatomical Cutaway`, `Phantom High-speed 1000fps`, `Epic Drone Aerial Sweep` 等）。
  4. **每个 Scene 必须额外标注两个字段（用于批量生成与成本控制）**：
     - `【建议生成时长】`：`10s`（默认）或 `12s`。**注意**：现有素材实测为 24fps × 240 帧 = 10.0 秒，切一半只剩 5 秒不够用；生成时优先选 **12 秒**留裁切余量。
     - `【分辨率】`：**统一填 `1080p`**。历史教训：1.2 生成的 18 个片段里 16 个是 720p，成片放大后发糊。
  5. **场景数量控制**：按「每 5–6 秒旁白 = 1 个 Scene」换算。**6.5 分钟旁白约需 18 个 Scene；7.5 分钟约需 22–25 个 Scene**。若少于该数量，说明单 Scene 承载的旁白过长，画面会与解说脱节。

---

### 第五步：生成文件四 —— 英文提示词纯文本（批量生成用）

* **文件名**：`{章节名}_Prompts.txt`（如 `1.2 橡胶的自然属性_Prompts.txt`）
* **定位**：给「一次生成一整批」的场景使用。有些工具只吃纯文本、每行一条；有些需要一条一条贴。这个文件让两种用法都不用从 md 里手工挑。
* **内容规范**：
  1. **每行一条**，格式：`Scene 01 | {英文提示词全文}`，行内不得换行。
  2. **只含英文提示词**，不含中文、不含字段名、不含 Markdown 标记。
  3. 行首 `Scene NN` 保留，方便出片后回填文件名。
  4. 文件末尾额外附一段 **【批量生成前置约定】**，写明：全局画幅 `16:9`、分辨率 `1080p`、帧率 `24fps`、全局风格基调串（各条提示词里可省略的公共前缀）。

---

### 第六步：生成文件五 —— 字幕校对表

* **文件名**：`{章节名}_字幕校对表.md`
* **定位**：**这一步是本工作流最重要的质量关卡，不可跳过。**
* **为什么必须有**：`<sub alias>` 只能保护「多音字和数字读法」，**保护不了「TTS 听错但字面没错」的同音错字**。1.2 与 1.1 的实战中已出现下列真实错误：
  - `汁液` 被转写成 `枝叶`（出现 2 次，且已混进成片字幕）
  - `顺式-1,4-聚异戊二烯` → `顺势一四聚一五二烯`（两处都错：构型字 + 五/戊）
  - `熵弹性` → `商谈性`（物理核心概念被毁）
  - `固特异` → `故特意`
  - `胶工` → `交工`；`乳胶` → 漏字
* **内容规范**：
  1. **易错专名清单**：从本章脚本中穷举所有「人名 / 地名 / 物种学名 / 化学式 / 物理概念 / 机构名」，列成表格，三列：`正确写法` | `常见误转写` | `必须出现的幕次`。
  2. **逐幕清单**：按幕次列出该幕的专名，便于出字幕时对照。
  3. **TTS 后校验命令**：给出可直接执行的 Python/grep 片段，扫描 SRT 命中误转写词并打印行号。约定用 **UTF-8 编码读 SRT**（现有 srt 多为 utf-8-sig，须用 `encoding='utf-8-sig'`）。
  4. **本次新增词条必须回填**到 `references/ssml_pronunciation_rules.md`，否则下一集会重复犯同样的错。

## 输出目录结构（交付物）

```
旁白/{章节名}/
├── {章节名}.md                      # 文件一：导演分镜脚本
├── {章节名}_SSML.md                 # 文件二：TTS 发音标记
├── {章节名}_Google_Flow_提示词.md    # 文件三：逐句对齐提示词（含中英对照）
├── {章节名}_Prompts.txt             # 文件四：英文提示词纯文本（批量用）
└── {章节名}_字幕校对表.md            # 文件五：易错专名清单 + 校验命令
```

## 交付与验证清单

在完成生成后，确认以下清单：
- [ ] 是否在 `旁白` 下新建了专属子文件夹？
- [ ] 子文件夹内是否完整包含了上述 **5** 个规范命名的文件？
- [ ] 脚本、SSML 与视频提示词的内容节奏是否 100% 互相呼应？
- [ ] SSML 中所有易误读的化学式、数值、单位是否均已使用 `<sub alias="...">` 做了发音保护？
- [ ] 提示词是否具备英文标准 Prompt 并符合 Google Flow 7 层公式？
- [ ] **每个 Scene 是否标注了 `【建议生成时长】`（优先 12s）与 `【分辨率】1080p`？**
- [ ] **Scene 总数是否 ≥ 「旁白分钟数 × 3」**（6.5 分钟 ≥ 18 个，7.5 分钟 ≥ 22 个）？
- [ ] **是否产出了 `_字幕校对表.md`，且其中每个专名都填了「常见误转写」？**
- [ ] **本次新发现的误转写词条是否已回填 `references/ssml_pronunciation_rules.md`？**

## 已知坑位备忘（来自 1.1 / 1.2 实战）

| 坑 | 现象 | 规避 |
|---|---|---|
| 时间估算失真 | 脚本元信息写 200–210 字/分，实测成片配音是 **258–264 字/分**（1.1 = 258，1.2 = 264） | 写元信息时按 **260 字/分**估时长，别按 210 |
| 素材时长过短 | 24fps × 240 帧 = 10.0s，切一半剩 5s | 生成时选 **12s** |
| 分辨率不统一 | 1.2 的 18 个片段里 16 个 720p、2 个 1080p | 统一 **1080p** |
| 素材自带空音轨 | 素材 codec 含 aac、时长 0:00，某些播放器会读成静音轨 | 合成时**显式丢弃素材音轨**（`-an` 或映射时只取 v:0） |
| 帧率混用 | 1.1 成片 30fps，部分素材 24fps | 时间线帧率跟随主要素材（24fps），或统一转码 |
| 双版本字幕 | 1.2 存在 `01.srt`(4:17，内容不完整) 与 `1788659131_9467.srt`(7:14，完整) 两版 | 认清哪版对应完整脚本，**弃用不完整版** |
